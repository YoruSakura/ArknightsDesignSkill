FORGEKIT // FORM STATE ENGINE

ForgeKit 是一套面向复杂多步表单与工业配置向导的零依赖状态机库。它将字段验证、异步提交锁与可访问性焦点管理统一收敛为确定性状态迁移，避免在组件树中散落相互冲突的布尔标志。

阅读原型提示：本页完整演示 Endfield UI 的「三栏技术文档站」骨架（.ef-docs-shell + .ef-prose + .ef-toc），严守纸墨可读性，全页克制保留 1 处信号黄标记。

一、架构概览与安装

常规前端表单库往往与特定渲染框架强绑定，而在多框架工程或原生 Web Components 场景下，状态流转本身应当保持纯粹。ForgeKit 采用单向事件队列驱动，gzip 后体积仅 3.8 KB。 

npm install @forgekit/core
# 或使用 pnpm 离线镜像源
pnpm add @forgekit/core

「状态机的价值不在于增加抽象层，而在于让非法中间态在类型与运行时层面都不可能被构造出来。」

二、声明式状态机与字段校验

每个向导流程由有限个具名步骤组成：idle、validating、submitting 与 completed。当任一必填字段未通过规则时，状态机自动阻断迁移并将焦点引导至首个报错输入项。

三、createMachine() API 参数表

所有配置项均支持静态类型推导；窄屏视口下参数表自动包裹 .ef-table-wrap 避免挤压正文列。

参数名 类型 默认值 说明
initial string "idle" 初始激活步骤名称，须存在于 steps 键集合中
validateOnBlur boolean true 失焦时执行字段级增量校验并同步 aria-invalid
focusFirstError boolean true 提交失败时自动聚焦首个报错字段，保障键盘与读屏无障碍
retryLimit number 2 网络抖动时允许的幂等提交重试次数上限

四、多框架接入配方

通过标准 WAI-ARIA 页签切换不同运行环境的最小接入代码（支持键盘 ← / → / Home / End）：

import { createMachine } from '@forgekit/core';

const flow = createMachine({
  initial: 'account',
  validateOnBlur: true,
  focusFirstError: true,
});

flow.send({ type: 'NEXT', payload: { email: 'ops@example.com' } });
import { useMachine } from '@forgekit/react';

export function OnboardingForm() {
  const { step, errors, next } = useMachine(onboardingSpec);
  return <button onClick={next}>Step {step}</button>;
}
import { useForgeMachine } from '@forgekit/vue';

const { currentStep, submit, isValid } = useForgeMachine(onboardingSpec);
